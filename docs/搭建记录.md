## 2. 技术设计

- 官方 `pytorch/pytorch:2.7.1-cuda12.6-cudnn9-runtime` 作为唯一训练基础镜像；兼容性最终由容器 CUDA 实测确定。
- 固定 Transformers 4.53.3、PEFT 0.16.0、Accelerate 1.9.0 等直接依赖；不额外安装替代 PyTorch。
- LoRA + BF16 + SDPA + gradient checkpointing；不要求安装 FlashAttention CUDA 扩展。
- 模型编码遵循 Qwen 官方最后 token 池化、L2 normalization、query 指令和 document 无指令约定。
- 使用显式负样本 InfoNCE，每个 query 独立候选集合，防止不加区分地引入 in-batch 假负例。
- 数据治理与模型训练分离，为 ReRank/LLM 复用下载、文档处理、数据版本和分组能力。

## 4. 网络处理记录

服务器直接访问 huggingface.co:443 出现连接拒绝，官方 PyTorch 镜像 3.32 GB 主层直拉速度较慢。采取临时 SSH 反向转发，将当前工作机已有的网络代理提供给**临时下载容器进程**；不修改宿主机代理、Docker daemon、DNS、证书或网络配置。

权重继续从官方 Hugging Face 下载，先解析 commit SHA 再下载；网络中断使用缓存续传及有限重试。镜像备用下载器 `scripts/pull_official_image.py` 从官方 Docker Hub 拉 manifest/config/layers，逐层 SHA256 校验后生成 Docker save tar，再用已有 Docker 加载。没有用第三方镜像替代官方内容。

Ubuntu archive 下载速度较低，实际构建通过 `APT_MIRROR=https://mirrors.tuna.tsinghua.edu.cn/ubuntu` 使用 Ubuntu 软件包镜像；仅修改 Docker 构建层内的 apt sources，仍使用 Ubuntu 签名校验。默认参数为空时保留官方软件源。PyPI 继续使用官方来源。

备用镜像下载脚本需要一个已有 Python 3.11 容器镜像及可用 HTTPS_PROXY。此次使用主机已有 `python:3.11-slim`，依赖只安装在临时容器文件系统。其 host network 仅用于访问绑定在 127.0.0.1 的临时转发端口，不授予特权、不挂载设备/系统目录；训练容器仍使用独立网络。完成后移除临时容器、关闭转发。
