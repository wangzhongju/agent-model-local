# 使用手册

## 1. 容器与环境

在 91 服务器的工程根目录操作。主机仅执行已有 Docker/Compose 和文件操作；不运行主机 pip/apt、驱动安装、sysctl 或 sudo。GPU 已有其他任务时，先用 `nvidia-smi` 查看空闲显存，不停止其他任务。

```bash
bash docker/docker.sh build
bash docker/docker.sh start
bash docker/docker.sh status
bash docker/docker.sh exec python -m aml.cli doctor
bash docker/docker.sh shell
```

以下章节的 `python` 命令均在容器 shell 的 `/workspace` 执行；也可添加前缀 `bash docker/docker.sh exec`。项目代码通过 `PYTHONPATH=/workspace/src` 生效，无需在主机安装。容器使用主机 UID/GID，产物属于 cdky，缓存放在工程 `.cache/`，不挂载主机 HOME。`stop` 删除本工程容器，不删除项目数据或其他容器。

可以在构建时通过环境变量指定 `PIP_INDEX_URL`；运行时可指定 `GPU_ID`、`DOCKER_IMAGE`、`CONTAINER_NAME`、`HF_ENDPOINT`。默认访问官方 PyPI/Hugging Face。更换镜像站应由使用者确认来源。私有模型的 HF_TOKEN 只通过环境变量注入，不写入配置、Git 或文档。网络参数变更后重新 `start` 使 Compose 重建容器。

本次服务器构建使用 `APT_MIRROR=https://mirrors.tuna.tsinghua.edu.cn/ubuntu bash docker/docker.sh build` 加快 Ubuntu 软件包下载；该参数只作用于镜像内部，省略时保留官方源。

## 2. 下载与版本追踪

```bash
python -m aml.cli download-model
python -m aml.cli download-dataset --output data/external/scifact
```

模型默认 `Qwen/Qwen3-Embedding-0.6B`。下载先解析具体 commit，再以 commit SHA 下载，记录 `download.json`；支持 `--revision <commit>`。Hugging Face 的 local_dir 缓存支持失败后续传；模型不要在同一目录切换版本，改用新目录。

数据示例为 BeIR/scifact 的 corpus、queries 及官方 **train** qrels（CC-BY-SA-4.0，保留归属与许可）。使用官方训练标签重新分组产生本地 train/dev/test；这是本地实验划分，不是官方 BEIR 测试分数。Hugging Face 网络失败会明确报错，不自动换成其他数据源。下载后训练、挖掘和评估使用本地文件，可离线执行。

### 91 服务器的下载网络

此次实测服务器无法直连 Hugging Face，已有模型和 SciFact 已完整缓存。后续新下载可用一次性下载容器，传入可用的 HTTPS_PROXY，无需修改服务器代理或 Docker daemon：

```bash
# 在服务器工程目录执行；代理地址替换为实际可达的地址
HTTPS_PROXY=http://可达代理地址:端口 bash docker/download.sh download-model
```

如果代理只在工作机本地监听，可在该工作机临时打开 SSH 反向转发（7897 替换为工作机已有代理端口）：

```bash
ssh -N -o ExitOnForwardFailure=yes -R 127.0.0.1:17897:127.0.0.1:7897 cdky@192.168.88.91
# 再在服务器工程目录执行：
DOWNLOAD_NETWORK=host HTTPS_PROXY=http://127.0.0.1:17897 \
  bash docker/download.sh download-dataset --output data/external/scifact
```

下载容器使用本工程镜像、普通 UID、无 GPU、仅项目目录挂载，任务结束自动删除。host 网络只用于这一临时下载容器访问本机转发端口；完成后关闭工作机 SSH 转发窗口。训练容器不依赖该通道。

```bash
python -m aml.cli prepare --corpus data/external/scifact/corpus.jsonl \
  --queries data/external/scifact/queries.jsonl --domain scifact --version v1
```

## 3. 自有文档到训练数据

将有使用权限的 PDF、DOCX、DOC、Markdown、TXT 放在 `data/domains/<领域>/raw/`。数据留在服务器容器及项目目录，本流程不调用外部 LLM 接口。

```bash
mkdir -p data/domains/industry/raw data/domains/industry/staging
# 将文档复制到 raw 后：
python -m aml.cli ingest --input data/domains/industry/raw \
  --output data/domains/industry/staging/corpus.jsonl --chunk-size 700 --overlap 100 --ocr
python -m aml.cli queries --corpus data/domains/industry/staging/corpus.jsonl \
  --output data/domains/industry/staging/queries.jsonl
```

PDF 文本页直接提取；`--ocr` 对无有效文本的页面使用 Tesseract 中英文 OCR。Word 表格一并提取；旧 DOC 在容器临时目录由 LibreOffice 转为 DOCX。OCR、复杂表格、多栏阅读顺序和 Word 页码可能不准确，必须抽查。DOCX 的 page=1 表示逻辑文档，不是假定 Word 实际分页。解析失败写入 `corpus.jsonl.report.json` 并返回非零；部分成功文件不能绕过错误直接发布。

文本标准化、内容去重后按字符窗口切分，保留 source/source_id/page/offset。默认 700 字符与模型 512 token 并非等价；中文或代码密集文本应减小 chunk-size（如 350），或经显存验证后提高 max_length。训练、挖掘、评估、部署使用一致最大长度和指令。当前窗口切分不是语义分段，跨页表格需预处理。

### 查询与正样本的审核

默认查询生成器根据标题生成模板，输出 `status=draft`，不能直接用于正式训练。可以人工改写 query/positive_ids，或下载独立指令模型进行本地生成：

```bash
python -m aml.cli download-model --repo Qwen/Qwen3-0.6B --output models/base/Qwen3-0.6B
python -m aml.cli queries --corpus data/domains/industry/staging/corpus.jsonl \
  --output data/domains/industry/staging/queries.jsonl --generator models/base/Qwen3-0.6B
```

本地生成器要求 JSON 结果、可在原文逐字定位的 evidence；不合格输出跳过。生成与 embedding 训练分进程运行，避免两套模型同时占显存。小模型不能保证问题质量或事实正确，仍需人工审核。

逐条确认问题与业务检索场景一致、证据足够、所有相关块均列入 positive_ids、无答案泄漏及敏感字段；将合格行设为 `status=approved`，不合格行删除或保留 draft。人工检索日志可直接按同一 JSONL 契约导入。至少 3 个独立查询文档组才能划分；有 4 个负样本时 dev 建议至少有 5 个独立文档，生产一般应准备更多独立文档和查询。

```bash
python -m aml.cli prepare --corpus data/domains/industry/staging/corpus.jsonl \
  --queries data/domains/industry/staging/queries.jsonl --domain industry --version v1
python -m aml.cli validate --root data/domains/industry/versions/v1
```

约 80/10/10 按文档连通组划分。相同 source、完全重复文本、多正样本跨文档、相同查询的文档连接到同一组，避免跨集合泄漏。语义近重复、不同版本的同一手册必须由数据管理员在导入前归为同 source_id；本工程没有宣称自动识别所有语义重复。修改已冻结数据会被 hash 校验拒绝；修订必须生成 v2。演示脚本显式使用 `--allow-draft`，禁止据此报告正式效果。

## 4. 负样本挖掘

```bash
root=data/domains/industry/versions/v1
for split in train dev; do
  python -m aml.cli mine --root "$root" --split "$split" --method bm25 \
    --negatives 4 --output "$root/embedding/bm25-v1/$split.jsonl"
done
# 基础模型 dense hard negative；适合词面差异较大的查询
for split in train dev; do
  python -m aml.cli mine --root "$root" --split "$split" --method dense \
    --model models/base/Qwen3-Embedding-0.6B --negatives 4 --margin 0.05 \
    --output "$root/embedding/dense-v1/$split.jsonl"
done
```

每个 split 仅在自己的语料中挖掘；排除全部已知正样本、同源文档和与正样本完全相同的文本。BM25 使用英文单词/中文单字词项，是无需 GPU 的启动基线；dense 使用归一化向量余弦分数，排除分数不低于 `最高正样本分数 - margin` 的候选，降低潜在伪负样本风险。保留分数、候选 ID、模型、数据 manifest hash。负样本不足时跳过并报告，不将正样本填入负样本，也不悄悄随机补齐；全空时直接失败。

审核 `*.report.json` 的保留比例，并抽查高分负样本。发现相关候选应补入 staging positive_ids、重建新数据版本后重新挖掘。逐步从 BM25 过渡到 dense；更强教师 ReRank 评分可未来接在候选过滤阶段。不要挖掘 test 训练数据。

## 5. LoRA 训练与断点续训

复制 `configs/embedding/qwen3-0.6b-lora.yaml` 为自己的配置，修改 dataset_root、train_file、dev_file、output_dir 和业务 instruction，正式训练删除或设 `allow_draft_data: false`。训练器默认拒绝以 `--allow-draft` 冻结的演示数据版本。每个实验使用新 output_dir，保留旧结果。

```bash
python -m aml.cli train --config configs/embedding/industry-v1.yaml --max-steps 2
# 正式训练：新 output_dir，去掉 --max-steps
python -m aml.cli train --config configs/embedding/industry-production.yaml
# 中断的同一实验恢复 optimizer/scheduler/RNG/global_step
python -m aml.cli train --config configs/embedding/industry-production.yaml \
  --resume runs/embedding/industry/qwen3-0.6b/lora-v1/checkpoint-100
```

默认 LoRA r=16/alpha=32/dropout=.05，q/k/v/o 投影；BF16、SDPA、gradient checkpointing，序列 512、batch=4、累积=8、4 个显式负样本、学习率 2e-4、3 epoch、cosine schedule。每条查询使用自己的 1 正 + N 负样本执行 InfoNCE；不把其他查询正样本直接当负样本，避免未知多正样本冲突。梯度累积增加有效优化 batch（默认 32 条 query），**不增加每条 query 的对比负样本数量**。多正样本全量用于过滤与评估，当前训练取 positive_ids 首项作为正例。

这是 24GB 起始配方，实际显存取决于文本长度与 GPU 共用情况。若 OOM：先减 batch_size（4→2→1）、再减 max_length/negatives；增加累积可维持有效优化 batch。不要为了训练停止其他服务或修改主机驱动。记录实际峰值显存 `gpu-memory.json`。

验证集 loss 用于选择最佳 checkpoint，adapter 目录保存最佳权重；checkpoint 含优化器等恢复状态，仅保留最近/最佳最多两个。`run.json` 记录配置、输入 hash、环境，`pip-freeze.txt` 记录完整依赖，`trainer_state.json` 记录损失曲线。恢复时使用同一数据、配置和依赖，不要把其他实验 checkpoint 当续训；迁移学习应创建新实验并明确初始化策略。

## 6. 检索评估、准入和导出

数据挖掘和配置完成后，也可使用通用编排脚本一次运行训练、dev/test 准入和导出；任一质量门槛失败即停止，报告目录与导出目录必须是新目录：

```bash
bash scripts/train_and_evaluate.sh configs/embedding/industry-production.yaml \
  data/domains/industry/versions/v1 runs/evaluation/industry/production-v1 \
  models/exports/embedding/industry/production-v1
```

以下为逐步运行方式，适合研究调参与诊断：

```bash
root=data/domains/industry/versions/v1
adapter=runs/embedding/industry/qwen3-0.6b/lora-v1/adapter
python -m aml.cli evaluate --root "$root" --split dev --output runs/evaluation/industry/base-dev.json
python -m aml.cli evaluate --root "$root" --split dev --adapter "$adapter" --output runs/evaluation/industry/lora-dev.json
# 配方冻结后，test 仅用于最终报告
python -m aml.cli evaluate --root "$root" --output runs/evaluation/industry/baseline.json
python -m aml.cli evaluate --root "$root" --adapter "$adapter" --output runs/evaluation/industry/candidate.json
python -m aml.cli compare --baseline runs/evaluation/industry/baseline.json \
  --candidate runs/evaluation/industry/candidate.json --output runs/evaluation/industry/comparison.json
python -m aml.cli export --adapter "$adapter" --output models/exports/embedding/industry/release-v1
python -m aml.cli search --root "$root" --model models/exports/embedding/industry/release-v1 \
  --query '输入一个实际业务问题'
```

如果使用自定义 instruction/max_length，evaluate/search/mine 必须传相同值；导出包保留 embedding_config.json 和 Sentence Transformers 配置，部署时按其值使用。检索报告记录 Recall、MRR、nDCG @1/5/10，逐查询 top10 单独保存。查询仅来自指定 split，候选使用整个 corpus，避免只在小测试分区内检索造成过度乐观。指标为二值 relevance。

compare 要求数据、split、指令、长度和数量一致；默认 nDCG@10、Recall@10 不退化才通过，否则返回退出码 2。仅一次小样本无退化不代表可上线，还需生产代表性数据、通用能力保留、时延和容量验收。export 是手动发布准备步骤，失败的 quality gate 不应由自动发布流程忽略。

合并权重可由 Transformers AutoModel 或 Sentence Transformers 加载，容器已包含两者；`scripts/verify_export.py` 检查适配器、合并模型和 Sentence Transformers 三条加载路径的一致性。向量为最后有效 token pooling + L2 normalize；query 按 `Instruct: ...\nQuery:...` 加指令，document 不加。更换模型后必须重建知识库所有文档向量，禁止新旧向量混用。当前只验证默认 1024 维，不对其他截断维度作效果承诺。

## 7. ReRank/LLM 复用

```bash
python -m aml.cli convert --task reranker --input "$root/embedding/bm25-v1/train.jsonl" \
  --output "$root/reranker/pairs/train.jsonl"
python -m aml.cli convert --task llm --input "$root/embedding/bm25-v1/train.jsonl" \
  --output "$root/llm/annotation/train.jsonl"
```

ReRank 导出 query/document/二值 label。LLM 仅导出 question/context/待标注 answer，不把检索文档冒充回答；人工添加 grounded answer 后再编写 SFT 训练器。具体模型的损失、模板、评估各归属独立模块，共用下载、原始文档、语料与数据分区。

## 8. 日常维护与故障排查

- 下载超时：检查容器网络和 Hugging Face 可达性，重跑同目录续传；保留日志，不修改宿主机代理/证书。
- CUDA 不可用：运行 doctor、检查 Compose GPU 声明与已有 runtime；宿主机缺失的依赖报告管理员处理。
- 数据不足：增加独立文档和审核查询，或降低 negative 数并同步训练配置；不要随机拆分相邻块。
- 训练 loss 降而检索指标降：检查伪负样本、模板查询偏差、学习率/epoch、任务指令以及基线截断长度。
- PDF/Word 异常：查解析报告，用容器内 OCR/转换；复杂版式人工清理。
- 磁盘不足：用 `du` 审查本工程缓存、checkpoint 与导出，人工决定清理；脚本不执行全局 Docker prune。
- 备份：原始文档、冻结版本、manifest、configs、adapter、评估报告应一起备份；基础权重可按 commit 重下。

运行 `python -m aml.cli --help` 或子命令 `--help` 查看完整参数。
