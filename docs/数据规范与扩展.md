# 数据规范与扩展

## 层次和契约

`raw → staging → versioned corpus/queries → task-specific samples → experiment → export`。

共享的是原始语料与数据治理，不共享混杂的模型训练目录。模型基础权重按模型名/版本保存；训练配置和 checkpoint 按 task/domain/model/experiment 保存。每个版本视为不可变快照，禁止以同名文件替换内容后继续训练。

corpus.jsonl 每行：

```json
{"id":"chunk_id","source_id":"document_content_hash","text":"可检索片段","source":"manual.pdf","page":3,"offset":0,"title":"手册章节","split":"train"}
```

staging 不需要 split，prepare 根据 source_id 和关联关系生成。id 全局唯一，source_id 表示防止拆分泄漏的原始文档组；手册不同版本可人工归入同一 source_id。source/page/offset 是追溯信息，不能作为监督标签。

查询文件每行：

```json
{"id":"query_id","query":"如何申请临时访问权限？","positive_ids":["chunk_id"],"status":"approved","evidence":"相关原文","method":"human"}
```

多个正样本使用 positive_ids 数组。审核状态不等于事实正确的自动证明，数据负责人应保存审核依据。prepare 合并相同规范化查询的正样本，不允许同一查询跨集合。完全重复内容连通到同一分组；未标注的文档默认进入 train 作为候选，其关联 source 仍遵守既有分区。

挖掘数据每行：

```json
{"id":"query_id","query":"如何申请临时访问权限？","positive_ids":["chunk_id"],"positive":"正样本文本","negatives":["其他文档内容"],"negative_ids":["negative_id"],"split":"train","mining":{"method":"bm25","positive_score":2.1,"candidates":[{"id":"negative_id","score":1.5}]}}
```

报告记录输出 hash 和上游 manifest hash；训练重新校验来源和文件完整性，防止误用另一领域数据。训练器当前每 query 使用第一个正样本及固定数量负样本；若需要覆盖其他正例，可扩展采样器轮换，不能把它们当作负例。

## 模块职责

| 模块 | 职责 | 可复用范围 |
|---|---|---|
| common.py | JSONL、hash、分组、版本路径 | 全部任务 |
| documents.py | 文档转换/OCR/切块与来源 | 全部任务 |
| data.py | HF 下载、查询生成、审核导入、划分、验证 | 全部任务 |
| retrieval.py | 挖掘、检索评估、报告比较 | Embedding 与 ReRank 数据准备 |
| embedding.py | Qwen 池化、指令、推理、合并导出 | Embedding 专用 |
| training.py | PEFT LoRA 对比学习、checkpoint | Embedding 专用 |
| cli.py | 参数入口、任务数据转换 | 全部任务编排 |

新增 ReRank：在 `src/aml/reranker/` 添加模型加载、损失与评估，配置放 `configs/reranker/`，从 `convert --task reranker` 的独立样本目录读取。应按模型官方 query/document 模板训练，评价排序 nDCG/MRR，避免复用 embedding 池化。

新增 LLM：在 `src/aml/llm/` 实现 SFT、assistant token loss mask、生成评估；只从人工审核答案生成 messages。共享 docs 不等于可以直接复用 embedding 三元组作为聊天训练标签。输出放 runs/llm 和 models/exports/llm。

## 数据与发布质量关口

1. 解析失败非零退出；检查 OCR 和表格。
2. 正式样本必须 approved；至少三个独立组。
3. 数据版本 hash 与跨 split 泄漏校验。
4. 挖掘排除全部正样本与同源文档，报告不足候选。
5. 训练保存配置、数据 hash、依赖、随机种子和 GPU 峰值。
6. dev 用于选择配方；冻结后报告 test，对比相同完整检索库。
7. 检索准入通过且人工业务抽查完成后再发布，保留基础模型回退路径。

规模限制：当前语料与向量保存在 CPU 内存，dense scoring 每 query 一个 N 长数组，无 N×N 全量相似度矩阵。适合单机领域数据，百万级 corpus 应增加磁盘向量索引、分片加载和 ANN，并重新验证精确/近似指标差异。
